**Spec:** docs/templar/specs/2026-10-11-app-seo.md
**Profile note:** No money paths: implementation and review on the standard tier. t1, t5, t7, t10 and t11 hold the logic worth a careful review; t3, t13 and t15 are content/config. ## Global constraints
- Node 20 (as `frontend/nixpacks.toml`). API is ESM/CJS mix as in `frontend/api`; new API files follow the neighbouring style (`.mjs` libs, `.js` handlers).
- Tests use `node --test` like the existing `test:*` scripts in `frontend/package.json`; add one `test:seo` script that runs every new test file.
- Do not change unrelated logic. Never touch create/buy/sell or any transaction code.
- All user-facing copy: no em dashes, no slogan patterns, concrete facts, chains named "BNB Chain", "Solana", "Robinhood Chain".
- Every value put into HTML or XML is escaped. No wallet, cookie or session data in rendered HTML or caches.
- Canonical origin is `https://app.memewar.zone`; use one constant, overridable by env `APP_PUBLIC_ORIGIN` on the API.
- Before each PR: `npm ci` in `frontend/`, `npx tsc -p tsconfig.app.json --noEmit`, `npm run build`, `npm run test:seo`, all green (memory rule: real install, no symlinked node_modules).
- PRs target `build/cross-chain-stabilization-rh-base`; the founder merges and applies nginx changes in Coolify (redeploy, not restart).

### Task 7: nginx config file, base rules            [id: t7]
**Depends-on:** [t1]
**TDD:** required
**Files:** deploy/nginx/app.conf (new, repo root), frontend/shared/seoNginx.test.mjs, docs/release/GO_LIVE_STEP_BY_STEP.md (point the "App security headers" section at the file)
Start from the config in `GO_LIVE_STEP_BY_STEP.md:41-66`, then add per spec §3.4 (PR A part). Required mechanics:
- Keep the existing blocks byte-for-byte except the modifier: `location ^~ /embed/chart/` (rewrite + crypticpump CSP, plus noindex) and `location ^~ /assets/`. Add a separate `location ^~ /embed/` that only adds noindex and serves `/index.html`. No regex location can take these over.
- `absolute_redirect off;` at server level: TLS ends at the Coolify proxy and the container listens on port 80, so absolute redirects would point to `http://`. With it off, `Location` is relative (`/league`).
- `location = / { try_files /index.html =404; }` with security headers (without `$uri/` the home page would otherwise 404); t13 turns it into the proxy.
- Security headers repeated with `always` in every location that adds any header (nginx does not inherit `add_header`), including named and internal locations. The expected header set is defined per location: default set for app routes; `/embed/chart/` keeps the crypticpump CSP and no X-Frame-Options; `/assets/` keeps nosniff, CSP and Cache-Control as today.
- 301 aliases with anchored `rewrite ... permanent` (keeps the query string, escapes the target), captures restricted to `[A-Za-z0-9_.-]+` per segment, e.g. `rewrite ^/tournament/([A-Za-z0-9_.-]+)$ /warzone/tournaments/$1 permanent;`. Trailing slashes: `rewrite ^/(.+)/$ /$1 permanent;` before the allowlist., plus `location = /index { return 301 /; }` (`$uri.html` would otherwise serve a copy of `/`). `/index.html` itself stays a plain file with no redirect: the API renderer fetches it as the app shell, and a redirect to `/` would loop through the renderer.
- `X-Robots-Tag: noindex` via `map $request_uri $robots_tag` (regex ignores the query; `$uri` is `/index.html` after a fallback, so it cannot be used), added in the shared header set (empty value sends no header).
- Regex locations in this file order: aliases, (t13: entity proxy regexes), allowlist. Known SPA routes: one regex allowlist location using `try_files $uri $uri.html /index.html;` (200). Default `location /`: `try_files $uri $uri.html =404;` with `error_page 404 /index.html;` (no `=`, so status stays 404 and the body is the app, which shows its 404 screen).
- `location = /sitemap.xml` and `location ^~ /sitemaps/` proxied to the API with `resolver 127.0.0.11 1.1.1.1 valid=30s;`, `set $api https://api.memewar.zone;`, `proxy_pass $api$request_uri;`, `proxy_ssl_server_name on;`, `proxy_set_header Host api.memewar.zone;`, empty `Cookie` and `Authorization`, `proxy_hide_header Set-Cookie;`, connect 1 s / read 5 s.
Test (`seoNginx.test.mjs`, parses the conf):
- every `path=` in `src/App.tsx` (catch-all `*` excluded, `:param` replaced by a sample, `/*` by a sample segment) matches the allowlist regex or an alias or a `^~` block;
- every alias in spec §1.3 has a 301 with the right target;
- the test evaluates locations the way nginx does (exact, then longest `^~` prefix, then regexes in file order, then longest prefix) and asserts the winning location per sample, including `/` → the exact location;
- unknown samples (`/nope`, `/token`, `/warzone/x/y/z`) fall to the default location (404); `/coins/` gets a 301 to `/coins`;
- the robots map matches every noindex sample (`/drafts/x`, `/live`, `/import`, `/profile/w/command/x`) and no index sample;
- `/embed/chart/101/x` and `/assets/x.js` resolve to their `^~` blocks;
- every location carries its expected header set (per location, as above).
- the conf contains `absolute_redirect off`.
**Verify:** `cd frontend && node --test shared/seoNginx.test.mjs` → all pass; `docker run --rm -v "$PWD/../deploy/nginx/app.conf:/etc/nginx/conf.d/default.conf:ro" nginx:1.27-alpine nginx -t` → `syntax is ok` (if docker is unavailable, say so in the PR).
