# App SEO for app.memewar.zone — spec

Status: approved by the founder 2026-10-11 (decisions in §2). Source investigation: session of
2026-10-11, route inventory of `frontend/src/App.tsx`, live probes of app.memewar.zone.

## 1. Facts (verified 2026-10-11)

### 1.1 Hosting
- The app is a static Vite build served by nginx (Coolify, static site). The custom nginx config in
  use is the one in `docs/release/GO_LIVE_STEP_BY_STEP.md:38-66` (live headers match it). nginx
  ignores `public/_redirects`, `public/_headers` and `netlify.toml`.
- Current `location /` is `try_files $uri $uri/ /index.html`: real files are served, everything else
  gets `index.html` with status 200. `$uri.html` is not tried.
- A change to the nginx config only applies after a redeploy in Coolify. The founder applies it.
- The API (api.memewar.zone) is a separate Coolify service (Express, `frontend/api/server.mjs`).
  Its build has its own `VITE_*` env, so its local `dist/index.html` must not be used as the app shell.
- Live build flags: postgrad, arena, battle, league, tournament, events, war room, project imports
  are all on.

### 1.2 Current SEO defects
1. `/sitemap.xml` returns the SPA shell (HTML, 200). No sitemap exists anywhere.
2. `index.html` has `<link rel="canonical" href="https://app.memewar.zone/">`, served for every route.
3. Only the tab title changes per route (`src/hooks/useDocumentTitle.ts`, coarse map). No route sets
   description, canonical, OG or JSON-LD. No structured data at all.
4. Unknown URLs return 200 (soft 404). `NotFound` sets no `noindex`.
5. Aliases redirect client-side only (`<Navigate>`): duplicate URLs for crawlers.
6. `robots.txt` has no `Sitemap:` and no `Disallow`. `/r/:code` POSTs a referral capture on load.
7. Body is an empty `#root`; crawlers without JS see nothing. Netlify crawler handlers for
   `/prepare/*` and `/warzone/battles/*` stopped working after the move to nginx.
8. Meta description says "BNB + Solana" (Robinhood Chain missing).
9. The `/coins` search has no URL parameter (search arrives via the `memewarzone:homeSearch` event).

### 1.3 Route classification
- **Index, fixed URLs:** `/`, `/coins`, `/warzone`, `/warzone/battles`, `/warzone/major-war-league`,
  `/warzone/tournaments`, `/league`, `/war-room`, `/airdrops`, `/airdrops/winners`, `/recruiters`,
  `/squads`, `/playbook`, `/sponsorships/apply`, `/create`.
- **Index, per entity:** `/token/:id`, `/warzone/battles/:id`, `/warzone/tournaments/:id`,
  `/prepare/:slug` (public drafts only), `/post/:id`, `/recruiters/:code`, `/profile/:wallet`
  (eligible profiles only, §2).
- **Noindex:** `/profile/:wallet/command/**`, `/profile` (no id), `/drafts/**`, `/token/:id/edit`,
  `/live`, `/import`, `/recruiter`, `/recruiter/signup`, `/warzone/verify-email`, `/status`,
  `/embed/**`, `/story/**`, NotFound.
- **Blocked in robots.txt:** `/r/`, `/embed/`.
- **301 aliases:** `/leagues`→`/league`; `/feed`→`/`; `/docs`→`/playbook`; `/arena`→`/warzone`;
  `/arena/*`→`/warzone/*`; `/warzone/leagues`→`/warzone/major-war-league`; `/events` and
  `/warzone/events`→`/warzone/tournaments`; `/tournament/:id` and `/warzone/tournament/:id`→
  `/warzone/tournaments/:id`; `/battle/:id`→`/warzone/battles/:id`; `/command/feed`→`/`.
  (`/command/*` and `/recruiter-dashboard`, `/squad-dashboard` stay client-side: they need the
  connected wallet. They are noindex via the shell.)

### 1.4 Sitemap sources (API)
- Coins: `campaigns` table via the `/api/campaigns` logic (chains 56, 101, 4663; excludes publicly
  hidden campaigns); imported coins via `/api/arena/imports`.
- Battles: `/api/arena/battles` (live, queue, archived). Tournaments: `/api/arena/tournaments`.
- Recruiters: active recruiters (`/api/recruiters` logic, no 250 cap in the sitemap query).
- Posts: feed posts (`/api/feed/posts` logic). Prepare: public `campaign_drafts.slug`.
- Profiles: wallets with a handle or a launched coin (§2).
- Existing crawler HTML handlers: `api/battle-og.js` (`/api/battle-og/:id`), `api/prepare-og.js`
  (`/api/prepare-og/:slug`), `api/story.js` (`/s/:chain/:token`).

## 2. Decisions (founder, 2026-10-11)
1. Index posts. Index profiles only when they have a handle or a launched coin. Story pages noindex.
2. Every page load of the per-entity routes in §1.3 goes through an API HTML renderer. People and
   crawlers get the same HTML. The renderer caches for about 60 seconds. If the API fails or is
   slow, nginx serves the plain `index.html`.
3. Visible explainer copy is added to `/warzone/battles`, `/warzone`, `/warzone/major-war-league`,
   `/league`, `/airdrops`, `/recruiters`. Battle and scoring rules are checked against the resolver
   code before they are published. Copy follows the no-AI-tone rule (no em dashes, no slogans,
   concrete facts).
4. Structured data: Organization; SoftwareApplication with `name: "MemeWarzone"` and
   `applicationCategory: "FinanceApplication"` (the Google value for "Finance"); WebSite with a
   SearchAction targeting `/coins?q={search_term_string}`.
5. Ship as three PRs into `build/cross-chain-stabilization-rh-base`:
   A. sitemap, robots, app head tags and JSON-LD, nginx base rules;
   B. API HTML renderer + nginx proxy for entity and static routes;
   C. explainer copy.
   The founder merges each PR and applies the nginx config in Coolify.

## 3. Requirements

### 3.1 Sitemap
- `app.memewar.zone/sitemap.xml` is a sitemap index (XML, `application/xml`) listing child
  sitemaps under `app.memewar.zone/sitemaps/*.xml`. nginx proxies both paths to the API.
- Children: `static`, `coins`, `battles`, `tournaments`, `recruiters`, `posts`, `profiles`,
  `prepare`. Every `<loc>` is an absolute `https://app.memewar.zone/...` canonical URL. `<lastmod>`
  only where the source row has a real updated/created time. Max 50,000 URLs per file.
- Cached about 10 minutes. A failing source omits that child's rows; it never returns HTML.

### 3.2 robots.txt
- Adds `Sitemap: https://app.memewar.zone/sitemap.xml` and `Disallow: /r/` and `Disallow: /embed/`
  for all agents. Existing allow rules stay.

### 3.3 Shell and in-app head
- `index.html`: no static canonical; description names BNB Chain, Solana and Robinhood Chain;
  carries the JSON-LD of §2.4.
- In the app, every route sets title, description, canonical and `robots` meta (index or noindex
  per §1.3) on navigation. Canonical for a profile reached by `@handle` is the wallet URL. NotFound
  sets `noindex`.
- `/coins?q=<text>` pre-fills the coin search.

### 3.4 nginx (rules live in a file in the repo; the GO_LIVE doc points to it)
- 301 for every alias in §1.3.
- `X-Robots-Tag: noindex` on the noindex prefixes that nginx can match by path.
- `try_files` adds `$uri.html`.
- Known SPA route patterns return 200 with `index.html`. Anything else returns status 404 with
  `index.html` as the body (the app still shows its 404 screen).
- `/sitemap.xml` and `/sitemaps/` proxied to the API.
- PR B: entity routes and the fixed indexable routes proxied to the API renderer, with a short
  timeout and fallback to `index.html` on error. The renderer's 404 for a missing entity is passed
  through with the app shell as body.
- Existing security headers and the `/embed/chart/` and `/assets/` blocks stay as they are.

### 3.5 API HTML renderer (PR B)
- Fetches the live app shell from the app origin (static `index.html`, cached ~60 s), never from
  the API's own build.
- For each route in §3.4: injects title, description, canonical, robots, OG/Twitter tags, JSON-LD
  (per type, no `Product`: `WebPage`/`BreadcrumbList` for coins and profiles, `Event` for
  tournaments and battles where dates exist, `DiscussionForumPosting` for posts) and a short text
  summary inside `#root`, all escaped. React replaces `#root` on load.
- Missing or private entity: status 404 (or noindex for private drafts), same shell.
- Responses cached ~60 s per URL. No wallet, session or cookie data used.

### 3.6 Explainer copy (PR C)
- One shared content module holds the copy for the §2.3 pages. The app renders it visibly on those
  pages; the renderer includes the same text in the HTML it returns.
- Battle content: format, buy-ins, 75/20/5 split, boosts 90/10, scoring and winner rules (verified
  against code), Major War League, and how it differs from a launch-and-forget launchpad.

## 4. Out of scope
- Splitting the 5.2 MB main bundle (later).
- Docs site (done in PR #566).
- Any change to trade, create, buy or sell transaction code.
